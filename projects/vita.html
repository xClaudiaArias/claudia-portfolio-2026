VITA

A calmer way to navigate the job search.

A personal job-search companion designed to help applicants organize applications, prepare for interviews, manage resumes, and keep momentum during the job-search process.

Overview

VITA is a personal job-search companion — a single place to track applications, manage resumes, and prepare for interviews, instead of juggling spreadsheets, saved documents, and scattered browser tabs. It's built for job seekers, particularly students and early-career applicants, doing the day-to-day work of a search: sending applications, tracking where each one stands, and getting ready for interviews without losing momentum.

The problem

Job searching means managing a lot of moving pieces at once — resumes, applications, interview prep, usually spread across a spreadsheet, a resume folder, and whatever job board sent the last email. Nothing connects those pieces together, so it's easy to lose track of where an application stands or what needs to happen next. On top of that, most job-search tools are built like clinical dashboards that track outcomes without much regard for how discouraging a long search can feel.

This is based on my own experience going through a job search, rather than formal user research — I haven't run structured interviews or usability studies on this yet.

The approach

I wanted VITA to feel like a companion, not a scoreboard — something that supports momentum instead of just recording outcomes. Design priorities:

  • Keep resumes, applications, and interview prep connected instead of siloed
  • Encouraging language, an application can be marked "Not this time" instead of "Rejected," which feels less punishing in a process that already has a lot of rejection built in
  • Clear information hierarchy, so it's obvious what needs attention next
  • Enough structure to stay organized without the tool feeling like more homework
  • Accessible, responsive, and maintainable from the start, not bolted on later

Design & UX

The interface is organized around a small set of core areas — a dashboard, resumes, a resume scanner, an application tracker, a portfolio section, and interview prep, rather than one dense, everything-at-once view. The visual design was built as a custom system specifically for VITA, rather than pulled from a UI kit, so the "calm companion" feeling stays consistent throughout instead of being layered on top of default components.

Key features

Dashboard

A home base that surfaces what's active and needs attention, instead of requiring a trip through every section to find it.

Resume management with AI parsing

Resumes are parsed automatically so their content becomes structured, reusable data instead of a static file.

Resume scanner

Checks a resume against a specific job posting to help tailor it, rather than sending the same version everywhere.

Application tracker

Tracks where each application actually stands, using language that doesn't treat a "no" as a dead end.

Interview prep

A dedicated space to prepare for interviews tied to a specific application, instead of prepping in the abstract.

Portfolio

A place to keep portfolio-relevant material connected to the rest of the job-search process.

Technical implementation

VITA is a full-stack app: a React (Vite) frontend talking to a Node.js backend, with PostgreSQL as the database across a schema of about ten related tables, resumes, applications, interview prep, and more modeled as connected data rather than separate, disconnected records. Authentication uses JWTs. AI-assisted features, like resume parsing, call the Anthropic API.

Challenges & solutions

Challenge: local PostgreSQL environment conflicts

My machine had multiple competing PostgreSQL installations and versions, which caused connection and version-mismatch issues that were confusing to debug — the kind of problem that has nothing to do with the actual app but can stall progress for a while.

Solution

I tracked down and resolved the competing installations so the project could reliably connect to the right PostgreSQL instance, and documented the fix instead of solving it from memory next time.

Result

A stable local setup, and a clearer mental model of how PostgreSQL installations can conflict on macOS, something I now check for early on any new project.

Challenge: making status updates feel encouraging instead of punishing

A lot of job-search tools describe outcomes in blunt, clinical terms, "Rejected," "Declined", which can be discouraging over a long search.

Solution

I chose more neutral, momentum-oriented language throughout the app, for example, "Not this time" instead of "Rejected", so the product doesn't read like it's keeping score against the user.

Result

This is a design decision I'm still refining, I don't have user feedback on it yet, since VITA isn't in front of other users.

Accessibility & responsive design

VITA is still in development, so accessibility work is ongoing rather than finished:

  • Semantic HTML and heading structure throughout
  • Visible focus states on interactive elements
  • Responsive layouts for the core dashboard and tracker views
  • A full keyboard-navigation and screen-reader pass is still on the to-do list, not yet complete
  • Reduced-motion support and a color-contrast audit specific to VITA are planned but not yet verified

What I learned

Modeling resumes, applications, and interview prep as connected data rather than separate features bolted together forced me to think through the schema much earlier than I would have on a smaller project; about ten related tables ended up feeling like the right level of structure. I also learned that the local PostgreSQL conflicts I kept running into weren't a one-off fluke — documenting the fix properly saved me from re-debugging the exact same issue on a later project. On the product side, choosing language like "Not this time" over "Rejected" made me pay much closer attention to tone as a UX decision, not just a copywriting afterthought, small wording changes really do change how a tool feels to use.

Future improvements

  • Finish a full accessibility pass (screen reader and keyboard testing)
  • Add reduced-motion support specific to VITA's interface
  • Usability testing with real job seekers
  • Deploy a live demo
